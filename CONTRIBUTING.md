# Contributing to SpeeDNS

Thanks for helping improve SpeeDNS. Contributions should keep the tool
read-only, offline by default, and useful on both macOS and Linux.

## Before opening a pull request

Install Go 1.25 or newer, then run the local quality gates from the repository
root:

```sh
go test -count=1 ./...
go test -count=1 -race ./...
go vet ./...
bash scripts/coverage.sh
```

For changes that affect packaging or platform behavior, also run pure-Go builds
for all supported targets:

```bash
for target in darwin/amd64 darwin/arm64 linux/amd64 linux/arm64; do
  IFS=/ read -r goos goarch <<< "${target}"
  CGO_ENABLED=0 GOOS="${goos}" GOARCH="${goarch}" \
    go build -trimpath -o "speedns-${goos}-${goarch}" ./cmd/speedns
done
```

For a local GoReleaser snapshot, set the package timestamp from the checked-out
commit so the archive and package reproducibility check matches CI:

~~~bash
SOURCE_DATE_EPOCH="$(git show -s --format=%ct HEAD)" \
  goreleaser release --snapshot --clean --skip=sign
~~~

The repository CI also runs the domain-updater, live-smoke, release-script,
schema, package, and artifact fixtures. Normal tests must not depend on public
DNS or other Internet services; use the deterministic local fixtures instead.

## Code and benchmark changes

- Preserve the no-fallback rule between UDP, TCP, DoH, DoT, and DoQ.
- Do not weaken TLS certificate or hostname validation.
- Do not add DNS-setting changes, telemetry, or background network activity.
- Keep benchmark query matrices deterministic when a seed is supplied.
- Update `METHODOLOGY.md` when ranking, scoring, divergence, timing, or
  recommendation semantics change.
- Keep JSON schema changes additive unless a deliberate schema-version change
  is discussed first. CSV changes require corresponding consumer and fixture
  updates.
- Add an offline regression test for every transport, parser, report, or
  release-workflow behavior change.

## Data and generated files

The embedded domain corpus is pinned and must retain its Tranco attribution,
metadata, and checksum. Use `scripts/update-domains.sh` only for an intentional
maintainer refresh, review the generated data and metadata together, and run
`bash scripts/verify-domain-corpus.sh data` before committing a refresh.

Release archives, Debian packages, Homebrew casks, checksums, SBOMs, and
signatures are generated by the release workflow. Do not commit release output
or secrets to this repository. The Homebrew tap is maintained in the separate
`crypt0rr/homebrew-speedns` repository.

## Pull requests

Use a focused branch and explain the user-visible behavior, compatibility
impact, and verification performed. Link the relevant issue. Keep unrelated
formatting or dependency changes out of the pull request. Reviewers should be
able to reproduce the result without access to private resolver endpoints or
release credentials.
